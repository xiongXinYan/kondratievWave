## 这个模块解决什么问题

`08-monitoring/indicators.md` 定义了六维指标体系，但此前只有 ① 技术维有对应研究文件，②③④⑤⑥ 五维（合计 75% 权重）只有"看什么指标"，没有"为什么这个指标意味着什么"。

指标本身不解释任何事情。同一个"高收益债利差走阔"，在流动性冲击下和在信用基本面恶化下，含义完全相反。**没有机制文件，六维退化成六个猜谜用的数字。**

本模块就是补这个中间层：**把每个维度的因果机制写清楚，让指标有解释框架。**

## 一个必须先讲清的裁决：康波 vs 朱格拉

`01-theory/competing-cycle-theories.md` 明确写了：**朱格拉（7–11 年）是主力判断层，康波仅作背景**。但原六维体系里没有任何一维是朱格拉。

这是理论与执行脱节。本模块的处理方式：

- `capex-cycle.md` 承担朱格拉的落地：给出**可算的周期位置判据**（投资/GDP 偏离趋势、设备役龄结构、产能利用率、订单出货比）。
- 基钦（3–4 年）作为**节奏层**，只用于判断"这次下行是短期库存调整还是设备投资周期转折"，不进入长期判断。
- 康波在本模块中**只出现一次**：作为"技术红利处于生命周期的哪个位置"的定性背景，见 `04-technology/sixth-wave-hypotheses.md`。

**裁决结论**：任何复盘输出中，出现"周期位置"字样时，必须说明是哪个周期（朱格拉/基钦/康波）。不允许写"当前周期位置偏底部"这种不指明尺度的表述。

## 本模块的写作纪律

1. **不写预测年份**。写机制、写条件、写失效条件。
2. **不给概率**。理由同 `04-technology/sixth-wave-hypotheses.md`：会制造虚假精确性。
3. **机制必须可被证伪**。每份文件第八节都要写"出现什么，本文就错了"。
4. **区分"结构"与"周期"**。人口、分配是结构变量，变化慢但不可逆；债务、库存是周期变量，会反复。混谈是最常见的错误。
