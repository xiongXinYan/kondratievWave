# Kondratiev Wave

## 长期经济周期与个人战略研究系统

研究长期经济周期、技术革命、全球产业变迁及资产价格之间的关系，探索未来 5～10 年的职业发展、资产配置和风险管理策略。

**V1.2 · 时点口径、可证伪标准与周期嵌套**

---

## 这是什么，不是什么

| 是 | 不是 |
|---|---|
| 一个持续更新证据、修正判断的研究框架 | 一个康波知识库 |
| 研究"未来经济和产业可能往哪走" | 预测下一轮康波的具体拐点年份 |
| 情景分析 + 观察条件 + 失效条件 | 春夏秋冬的择时信号 |
| 与 `investment` 仓库分工的研究层 | 交易策略与仓位管理系统 |
| 一套能还原"当时知道什么"的时点记录 | 用最新修订数据写就的事后叙述 |

**核心原则**

- 不迷信周期
- 不预测精确拐点
- 不把历史相关性当成因果关系
- 用数据验证宏观判断
- 用情景分析管理未来不确定性
- **记录数据时点，不用今天的数据评价昨天的判断**
- **原始记录永久保留，结论可推翻，过程不重写**
- 用实际行动获得长期收益

---

## 三个问题三层分工

| 层次 | 回答什么 | 归属 |
|---|---|---|
| **康波研究** | 未来经济和产业可能往哪里发展？ | 本仓库 |
| **投资策略** | 什么资产值得配置？什么时候买？配置多少？ | `investment` 仓库 |
| **风险管理** | 如果宏观判断错误，如何控制损失？ | `investment` 仓库的风险约束层 |

本仓库只输出**方向、条件与证据**，不输出**仓位、买点与杠杆倍数**。

## 每份研究文件的统一格式

所有研究结论使用 `templates/research-template.md`，必含两个字段：

- **反对证据**：能推翻本文结论的事实
- **结论失效条件**：出现什么情况，本文判断就应作废

这两个字段不是装饰。它们的目的是防止整个项目逐渐变成一个只收集支持自己观点的信息库。V1.2 起，模板另要求填写**证据等级**与关键数据的**数据所属期 / 发布日期 / 修订状态**（见下节与 `08-monitoring/data-protocol.md`）。

---

## 证据质量分级（E-A ~ E-D）

给结论的可信度分级，**不给康波阶段打分、不给情景概率**。等级描述的是「支撑这个结论的证据有多硬」，不是「这个结论有多可能对」。

| 等级 | 研究状态 | 允许的表述 |
|---|---|---|
| **E-A** | 多来源一手数据支持，有较强因果证据 | 可作为后续推理的前提 |
| **E-B** | 多项证据支持，但因果链尚不完整 | 需注明缺口，不得当作定论 |
| **E-C** | 有一定证据，仍存在重要争议 | 必须并列反方观点 |
| **E-D** | 推测性假设，尚缺乏可靠验证 | 只能作为待观察假设，不得进入决策依据 |

**使用规则**

1. 每份研究文件在「核心结论」标注一个等级，并写明理由；等级变化须在 `CHANGELOG.md` 记录。
2. **与历史事件归因等级 A / B / C 是两套互不相关的标记**（见下方「归因原则」）。为避免混淆，证据等级一律带 `E-` 前缀；单独出现的 A/B/C 一律指归因等级或情景 A/B/C/D，须由上下文判明。
3. 等级只约束证据质量，不覆盖原有的「置信度：高 / 中 / 低」——后者描述判断把握，两者可同时存在且不一致（例如证据 E-A 但对未来外推的置信度仍为低）。
4. 来源性质标注（〔一手档案〕等）见 `09-sources/README.md`，它是 E 等级的输入之一，但不等同于 E 等级。

## 工作流：这套东西怎么用

文档写得再好，不跑就等于零。本仓库的运行节奏如下，**总耗时约每月 20 分钟 + 每季 90 分钟 + 每年半天**。

### 每月（20 分钟）

1. 复制 `08-monitoring/reviews/monthly/2026-11.md` 改名为当月，按 `08-monitoring/data-protocol.md` 的十列表填写。
2. 只记录**数据、方向与当时的第一反应**，不写分析；但必须填数据所属期、发布日期、统计口径、修订状态。
3. 在手记里写下"当时的第一反应"，不要修改。这一栏是后来自查"我到底是看出来的，还是编出来的"的唯一依据。

> 若某指标查不到月度数据，标「口径缺」，不要勉强填。这本身就是对指标体系的反馈。字段增加后若单月超过 40 分钟，应减少指标数量，而不是删字段。

### 每季（90 分钟）

1. 复制 `08-monitoring/reviews/quarterly/2026-Q4.md` 改名为当季。
2. 填六维变化 + 情景判断（**不给概率**）+ 四层周期位置与跨层冲突（见 `03-macro/cycle-nesting.md`）。
3. **对照 `08-monitoring/assumptions-ledger.md` 逐行更新状态**——不得跳行，不更新等于默认成立；状态变化的条目同步更新第六节假设卡片。
4. 检查是否有条目变为「已推翻」，若有，同时改来源文件并记 `CHANGELOG.md`。
5. 自评流程：哪一步做不下去，改流程，不要跳过。

### 每年（半天）

1. 复核结构变量（人口、分配）与所有「年度」频率条目。
2. 审慎评估是否调整六维权重。**权重调整必须同时更新 `08-monitoring/indicators.md` 第八节并记 `CHANGELOG.md`。**
3. 在 `reviews/annual/` 写一份**汇总与索引**：判断命中率、台账变化、口径与修订事件、指标体系反馈。**原始月度与季度记录永久保留，不删除、不覆盖、不回改**；发现历史数值被修订时在当期追加勘误，不修改归档文件。

> V1.1 曾规定「把 30 天前的月度记录按主题归并，删除原始文件」，V1.2 已废除。理由：这个项目最核心的资产不是某次结论，而是长期的判断记录；删掉原始记录，两年后就再也无法还原当时掌握了什么数据、第一反应是什么、哪些判断后来被证实或推翻。

### 何时重写整份文件

只看一个信号：**该文件的「结论失效条件」被触发**。情绪、新闻、市场波动都不是重写的理由。

## 多层周期嵌套

`03-macro/cycle-nesting.md` 给出四层周期的嵌套框架：长期结构周期（约 40–60 年）、中长期投资周期（约 15–25 年）、企业资本周期（约 7–11 年）、库存周期（约 3–5 年）。**这些是传统周期理论中的经验时间范围，不是固定周期或精确预测模型。**

它解决的具体问题是：长期技术趋势向上、中期基建仍在扩张、短期制造业却在去库存、而市场因流动性收缩下跌——这四件事可以同时为真。只看康波，容易把「长期看好」直接当成持有理由；分层记录则要求把每层方向、依据与冲突显式写出来，并按 R1（尺度对应）/ R2（冲突显式化）/ R3（事前登记）处理。

该框架对铜与有色、电网设备、AI 产业链的研究接口尤其重要：**长期叙事不能替代库存、订单与边际成本的短层判据**。规则详见 `03-macro/cycle-nesting.md`，季度复盘模板已接入。

---

## 分期原则：不只有一套年份

康波理论在学术上仍有争议。本仓库对每一轮分期都给四层：

1. **主流分期**（范·杜因 / 通行教材）
2. **不同学者的分期**（康德拉季耶夫本人、熊彼特、佩蕾丝、国内研究者等）
3. **本研究判断**（本仓库采用的口径）
4. **依据与置信度**（为什么这么定，以及在多大程度上可信）

这样出现新证据时，只需修订第四层，不必推翻整篇。

---

## 归因原则：区分"同期"与"因果"

历史上发生在萧条期的战争、饥荒、瘟疫，**不能一概视为康波出清的结果**。

本仓库对每个历史事件标注归因等级：

| 等级 | 含义 |
|---|---|
| **A** | 康波可解释：事件的主要驱动来自技术与资本周期 |
| **B** | 部分相关：宏观周期是背景条件之一，但不是直接原因 |
| **C** | 不可归因：主因是制度、宗教、民族、气候或偶发政治事件 |

只在 A 级事件上讨论"出清方式"，B 级作为背景，C 级不作为康波证据使用。

> 这里的 **A / B / C 只用于历史事件归因**，与上文的证据质量等级 **E-A ~ E-D**、情景编号 **A / B / C / D** 三者互不相干。引用时务必带上下文，不得简写互推。

## 数据与引用

- 所有关键数字标注：档位〔一手档案〕〔学术研究〕〔通行综述〕〔民间说法〕
- 估算区间优先于点估计
- 存在重大分歧的数字（如 1918 大流感死亡数）必须同时列出高低两派
- **三个日期分开**：数据所属期、发布日期、录入日期不得混写
- **时点数据（Point-in-Time）原则**：回测历史判断只能用当时可见的那一版数据；使用今天下载的最新修订序列评价过去的判断会产生前视偏差。若无版本历史，标注「不可回测」，不得假装
- **修订状态必填**：初值 / 修正值 / 终值 / 已回溯修订 / 口径变更 / 未修订；统计口径变更时不得与上期值直接比较

完整规则见 `08-monitoring/data-protocol.md`，数据源与版本历史（ALFRED、BEA Vintage History）见 `09-sources/data-sources.md`，引用分级见 `09-sources/README.md`。
