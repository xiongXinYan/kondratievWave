# 数据时点与修订协议（Point-in-Time）

**所属模块**：08-monitoring
**版本**：v1.2（新建）
**最后更新**：2026-11-14

---

## 一、这份文件解决什么问题

V1.1 的月度记录只有「指标 / 数值 / 方向 / 来源·发布月份」四列。它足以防止事后回忆偏差，但不足以支撑**两年后的回测**：

1. 只填「当前值」，没有上期值与数据所属期，无法复算变化方向；
2. 「发布月份」不等于「数据所属期」，两者混写会把 11 月发布的 9 月数据当成 11 月的数据；
3. 宏观数据会被修订。若 2027 年回看 2026 年的判断，用的是今天下载的最新修订序列，就等于用当时不可能知道的信息评价当时的判断——这是**前视偏差（look-ahead bias）**，会让一套并无预测力的框架在回测中显得很准。

本文件规定月度与季度记录的字段、修订状态与回测取数规则。**它不产生研究结论，只规定记录方式。**

---

## 二、三个日期必须分开

| 概念 | 定义 | 例子 |
|---|---|---|
| **数据所属期**（period） | 这个数字描述的是哪一段时间 | 2026 年三季度 GDP |
| **发布日期**（release date） | 该数值第一次对外发布的日子 | 2026-10-30 发布「初值」 |
| **录入日期**（as-of） | 本仓库把它抄进记录的日期 | 2026-11-05 |

三者任何一个缺失，历史判断都无法还原。「来源·发布月份」这一列在 V1.1 里同时承担了后两种含义，V1.2 起拆开。

---

## 三、月度记录字段字典

`reviews/monthly/` 下的每月文件（命名用年份与月份）中，每一行必须填满以下字段。查不到就写「口径缺」或「未发布」，**不得留空、不得用二手转述数字补齐**。

| 字段 | 作用 | 填写规则 |
|---|---|---|
| **指标名称** | 统一指标定义 | 必须与 `08-monitoring/indicators.md` 第四节的名称一致；自定义指标须在当季复盘补进该表 |
| **当前值** | 当月观测值 | 带单位；估算区间优先于点估计 |
| **上期值** | 用于比较 | 取上一次**同一口径**的观测值；口径变更时填「不可比」 |
| **方向** | ↑ / → / ↓ | 由当前值与上期值复算得出，不得凭印象填 |
| **数据所属期** | 避免期次混淆 | `YYYY-MM` 或 `YYYY-QN` |
| **发布日期** | 可重新核验 | `YYYY-MM-DD`；修订值另填修订发布日期 |
| **数据来源** | 能回溯 | 具体到机构与序列名（如 FRED `T10YIE`），不写「网上查到」 |
| **统计口径** | 避免口径变化 | 名义/实际、季调/非季调、同比/环比、税前/税后、原始/滚动 |
| **修订状态** | 识别历史数据被修正 | 见第四节枚举 |

> ⑦ 个必填项看起来多，但每月只需复制上月文件、改五个格子。若单月填写超过 40 分钟，应简化**指标数量**，而不是删掉字段——字段是回测能否成立的下限。

## 四、修订状态枚举（只允许这六种）

| 状态 | 含义 |
|---|---|
| **初值** | 首次发布，后续可能被改（如 BEA 季度 GDP 的 advance estimate） |
| **修正值** | 同口径下的第二次 / 第三次估计 |
| **终值** | 该轮常规修订结束后的数值 |
| **已回溯修订** | 年度更新或基准修订改写了历史序列 |
| **口径变更** | 定义、分类、基期或统计方法变了，**不得与上期值直接比较** |
| **未修订** | 该来源不修订历史值（如多数金融市场日度序列） |

**口径变更是最危险的一项**：它经常表现为「数据突然跳了一下」，很容易被当成周期转折。遇到时方向列填「不可比」，并在异常事件栏写明变更内容。

---

## 五、Point-in-Time 取数规则（硬约束）

1. **回测只能用当时可见值（vintage）**：判断 2026-Q4 的依据，必须是 2026-Q4 当时能拿到的那一版数据，不是今天能下载到的最新版。
2. **没有 vintage 数据就标注「不可回测」**：不得用最新修订序列假装成历史值。宁可少一条样本，不可制造虚假预测力。
3. **月度记录即最小可行的 vintage 存档**：只要每月按时填「当前值 + 发布日期 + 修订状态」，仓库自身就构成一份时点数据，无需等 V2.0 接入数据库。
4. **事后修订单独记录**：发现历史数值被修订时，在当期记录的「异常事件」栏追加一条说明（原值 / 新值 / 修订日期），**不回改已归档的月度文件**。
5. **历史回测的数据源**：优先使用带版本历史的存档库，见 `09-sources/data-sources.md` 的 ALFRED 与 BEA Vintage History 条目；序列无版本历史时，以本仓库归档的月度记录为准，并注明该限制。

### 5.1 一个真实案例（说明为什么这不是吹毛求疵）

圣路易斯联储用 ALFRED 复盘 2007Q4 美国实际 GDP：BEA 初值为年化 **+0.6%**；2008 年 7 月年度修订后变为 **−0.2%**；而当前版本约为 **+2.5%**。同期的 2007 年 12 月非农就业，初值 **+1.8 万**，当前版本 **+10.8 万**。

也就是说，用今天的数据回看，2008 年末几乎看不到衰退；用当时的数据看，衰退信号是明确的。**若用修订后的序列评价「当时是否该判断为衰退」，结论会系统性偏向乐观。** 该案例来源见 `09-sources/data-sources.md`。

## 六、留档规则：原始记录永久保留

| 动作 | 允许 | 说明 |
|---|---|---|
| 按主题做年度汇总 | ✅ | 只写进 `reviews/annual/` 的年度汇总文件，不改动原始文件 |
| 把月度记录复制到季度复盘表 | ✅ | 引用时注明来源月份 |
| 追加勘误说明 | ✅ | 写在当期「异常事件」或年度汇总，注明原值与新值 |
| 删除 / 覆盖 / 归并后回写原始月度文件 | ❌ | **禁止**。原始记录是本仓库最核心的资产 |
| 事后修改「当时的第一反应」 | ❌ | 写错也保留，否则无法区分「看出来」与「编出来」 |

理由：两年后回看，需要还原的是「当时掌握了什么数据、看到了什么风险、第一反应是什么、后来哪些被证实、哪些完全错了」。结论可以被推翻，过程不能重写。年度归档因此**只做汇总与索引，不做替换**，模板见 `08-monitoring/reviews/annual/README.md`。

## 七、数据来源优先级

1. 一手官方及其存档版本（FRED / ALFRED、BEA、BIS、OECD、世界银行、国家统计局、央行、IEA、CPB）
2. 行业协会与上市公司财报（须注明报告期与发布日期）
3. 媒体与研究机构（仅作线索，不得作为证据入表）

禁止用二手转述的数字直接入表。所有引用须遵守 `09-sources/README.md` 的来源分级与核验状态标注。
