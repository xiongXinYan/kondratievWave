**最后更新**：2026-11-14
**最近逐行复核**：尚未发生（首期定于 2026-Q4 季度复盘；V1.1 已完成登记，但未真实运转过一次）

## 一、这份文件解决什么问题

此前「结论失效条件」写在 20 多份文件各自的第八节里，**没有任何地方汇总"当前哪几条正在被触发"**。结果是一套设计精巧的自我纠错机制，实际上无法执行——因为复核时要翻 20 个文件。

台账把这些可证伪断言集中编号，一站复核。**它不新增研究内容，只让已有的机制可运行。**

V1.2 补了一层：紧凑表格只回答「什么会推翻它」，但一条真正可证伪的假设还需要**成立条件、观察指标、验证期限、支持与反对证据、最近更新日期**。第六节的「重点假设卡片」承载这些字段，分水岭条目与状态发生变化的条目必须建卡。

## 二、使用规则

### 2.1 状态枚举（只允许这六种）

| 状态 | 含义 |
|---|---|
| **成立** | 有证据支持，且未被有效反驳 |
| **待观察** | 无足够证据，方向不明 |
| **受挑战** | 出现反证但未足以推翻 |
| **未决** | 本仓库自身无法判定，需外部证据 |
| **已裁决** | 本仓库已做出取舍并执行（如权重分配、口径统一） |
| **已推翻** | 已被证据否定，相关文件必须改写 |

### 2.2 维护规则

1. **新增研究文件时，其第八节每一条失效条件必须在台账登记**，否则该文件视为未完成。
2. 季度复盘时逐行更新状态，**不得跳行、不得只更新"有变化"的行**——不更新等于默认成立。
3. 状态变为「已推翻」时，**必须同时修改来源文件并在 CHANGELOG 记录**，否则视为未完成。
4. 「已裁决」类不需要季度复核，只在裁决被质疑时重开。
5. 编号一旦分配**永不复用**。推翻的条目保留，状态改「已推翻」，加删除线说明。
6. **V1.2 起，新登记的断言必须同时具备九字段**（核心假设 / 支持证据 / 反对证据 / 观察指标 / 验证期限 / 成立条件 / 推翻条件 / 当前状态 / 最近更新日期），按第六节卡片格式登记；只有「什么会推翻它」而没有「成立条件」与「验证期限」的，视为登记未完成。
7. **验证期限是硬字段**：到期既未成立也未推翻的条目，状态改为「未决」或下调复核频率，并写明原因，不得静默续期。
8. 每次逐行复核后更新文件顶部的「最近逐行复核」日期。**未真正逐行走完之前不得填写该字段**——覆盖度 100% 不等于机制已经运转过。

### 2.3 编号规则

`T` 理论 · `H` 历史 · `A` 技术 · `M` 宏观 · `P` 个人与投资 · `S` 监测与情景。编号按登记顺序，不按重要性。

同一份来源文件可以有多条登记，但**每条必须能被单独推翻**。若一句话推翻时会连带推翻另外三条，应合并为一条，否则复核工作量被虚假放大。

### 2.4 卡片与表格的分工

| 场景 | 用哪种 |
|---|---|
| 存量 67 条的日常复核 | 第三节紧凑表格（断言 / 状态 / 推翻条件 / 复核频率） |
| 分水岭条目、状态发生变化的条目、所有新增条目 | 第六节完整卡片（九字段） |
| 已推翻条目 | 表格保留编号 + 卡片注明推翻日期与证据，均不删除 |

存量条目**不强制一次性补卡**；每次季度复核时，若某条状态变化或进入分水岭清单，当季补建卡片。这比给 67 行统一填一个日期更诚实，也不会制造虚假的「已复核」记录。

## 六、重点假设卡片（可证伪标准）

### 6.1 字段定义

紧凑表格只回答「什么会推翻它」。一条真正可证伪的假设还需要九个字段，缺一即视为登记未完成：

| 字段 | 要求 |
|---|---|
| 核心假设 | 一句话，**可被单独推翻**；不得把三条判断塞进一条 |
| 支持证据 | 至少 1 条，标明来源性质 |
| 反对证据 | 至少 1 条；检索不到须写明检索范围，不得写「无」 |
| 观察指标 | 可采集，指向 `08-monitoring/indicators.md` 中的统一名称，注明频率与统计口径 |
| 验证期限 | 具体季度。**到期既未成立也未推翻的，按 §2.2 第 7 条处理**，不得静默续期 |
| 成立条件 | **事前**写明、可判定；禁止「数据明显改善」这类事后可随意解释的表述 |
| 推翻条件 | 与成立条件对称，且与第三节表格「什么会推翻它」保持一致 |
| 当前状态 | 六枚举之一 |
| 最近更新日期 | `YYYY-MM-DD`；只改状态不改日期视为未完成 |

> 附加字段「证据等级」取 E-A ~ E-D（定义见根 `README.md`）。它描述证据硬度，不替代状态。

### 6.2 A-001 · AI 是否成为下一轮长期技术革命的核心驱动力

| 字段 | 内容 |
|---|---|
| 核心假设 | AI 是第六轮主导技术的**主要候选，未确认**（与第三节 A-001 一致） |
| 支持证据 | 2023 年以来大规模 AI 资本开支〔一手：行业财报〕；电力与电网投资因算力需求结构性上升〔行业研究〕；历史上「卖铲子」环节先受益〔学术研究〕（见 `04-technology/sixth-wave-hypotheses.md` §二） |
| 反对证据 | 美国 TFP 尚无趋势性回升（OECD / BLS，核心反证）；多数企业仍处试点、投资回报率不明；AI 替代「任务」而非「职业」，组织摩擦折损生产率；历史上被寄予厚望却未成为通用技术的案例不止一次（同文件 §三） |
| 观察指标 | ① 全社会劳动生产率：美国 TFP 增速、每小时产出（季度/年度，实际、季调）② 企业持续回报：AI 相关收入与留存、AI CAPEX / 收入、ROIC（季度，财报口径）③ 新产业与就业结构：非科技行业企业级渗透率、职业结构变化（半年/年度）④ 红利扩散：技术收益是否从少数科技公司扩散到制造、医疗、公共服务（年度，行业调研口径）。统一定义见 `08-monitoring/indicators.md` §4.1 |
| 验证期限 | **2027-Q2 复盘首次裁决**。届时若观测数据仍不可得，改「未决」并下调复核频率，写明原因；不得静默续期 |
| 成立条件 | 四条须同时出现：① TFP 连续 4–8 季度回升；② AI 相关企业收入与留存规模化兑现；③ 中位数实际工资上行；④ 渗透扩散至非科技行业 |
| 推翻条件 | **「CAPEX 退潮 + TFP 仍未升」的组合**（与 A-004 的既有裁决一致），或出现更强的候选技术集群。**仅 TFP 未升不构成证伪**——J 曲线意味着投入期产出被系统性低估（A-003） |
| 当前状态 | 待观察 |
| 最近更新日期 | 2026-11-14（建卡；状态沿用 V1.1 登记，未做新判断） |
| 证据等级（附加） | **E-C**：有一定证据，仍存在重要争议 |

> **为什么不能因为 CAPEX 增加就判定成立**：资本开支是投入端，不是技术兑现的证据。若开支持续增长而生产率与商业回报没有跟上，本假设应降级（受挑战），而不是靠「投入很大」维持待观察。这正是本卡片存在的原因。
